# 低温冷却管网巡检审计（中国邮路 / 转接耗时）

巡检机器人必须从指定检修口出发、回到原处，且至少走过每条管段一次。服务支持两种模式：

- **普通模式**：求解无向多重图上的**中国邮路 / 路由巡检问题**（管段长度为唯一成本）；
- **转接耗时模式**：可在每个节点为两条管段的**无序转接**填写非负整数耗时或禁行，在可重复经过管段的闭合行走空间中，以「管段长度之和 + 每次相邻转接耗时」为目标**直接全局求优**。

## 普通模式

- 在每条管段均走一次的基础上，选出需要**额外重复**的管段集合，使所有节点度数为偶数；
- 增加总长度**最小**；
- **精确给出全部同优集合数量**（按不同边集合计数，平行管段与等长最短路造成的分解歧义已去重）；
- 按**边标识字典序**生成 `0` 优先规范位向量并确定规范集合；
- 依据全部最优集合把每条管段标为 **必重复 / 可重复 / 从不重复**；
- 为规范集合生成一条从检修口起止、逐步可核对、副本数精确吻合的闭合欧拉路线。

## 转接耗时模式

- 沿用当前节点、管段与检修口；为**同一节点处两条不同管段的无序转接**填写耗时（非负整数）或 `禁行`/`-1`，**未填写视为零耗时**；
- 平行管段按标识区分，规则必须引用真实存在且在该节点相邻的两条管段；
- 启用该模式时管段**不超过 16 条**；
- 后端**不先固定**普通模式的最低增程集合再重排，而是把每条管段的两个有向穿越作为状态（≤32 个），在「覆盖管段位掩码 × 当前穿越状态」的状态空间上分层 Dijkstra，层内用已覆盖管段上的多源最短路闭包处理任意折返/掉头，**精确给出最优路线数**并输出全局最优；
- 同管段掉头（U-turn）始终允许且零耗时；禁行转接不会出现在任何结果路线中；若禁行规则使闭游不可行，返回「无可行闭游」并定位到规则表；
- 规范步骤在所有最优闭游中按**管段标识及方向序列的字典序**裁决；
- 结果展示**行走长度、转接耗时、总耗时**（= 两者之和）与逐步路线（每步标注进入该步支付的转接耗时）；点击某条转接规则，高亮规范路线中**全部命中位置**。

## 约束与校验

- 2–18 个唯一 ASCII 节点（非空白可打印字符）；
- 1–32 条管段（转接耗时模式下 1–16 条），唯一 ASCII 标识、正整数长度；
- 允许平行管段，禁止自环；
- 检修口必须是已声明节点；
- 断连、未知端点、重复标识、非法长度、不存在的检修口都会返回错误，并在页面定位到具体表/行；
- 转接规则的引用错误（未知节点/管段、同管段对、非相邻管段、重复规则、非法耗时）定位到规则表具体行；
- 审计失败时页面保留输入并清除旧结论。

## 算法要点（`app/solver.py`）

重复边集合是一个 T-join：重复边子图中恰为原奇度节点的节点度数为奇。

1. 全源 Dijkstra 得到奇度节点间最短路距离；
2. 奇度节点子集完美匹配 DP（O(2^k·k²)，k≤18）求最小增程；
3. 以匹配 DP 为门控，逐掩码合成“奇度锚点的一条最短路”与“剩余子问题的最优集合”的**对称差**，用整数掩码天然去重，得到**全部不同的最优 T-join**（小规模实测毫秒级）；
4. 集合按位向量（边标识序、`0` 优先）取最小者为规范集合；按边在全部最优集合中的出现情况分类；
5. Hierholzer 在扩展多重图上生成规范闭合路线，并对同边副本按经过次序编号。

**转接耗时模式**：状态为有向管段穿越 `d = 2·edge_index + 方向`（≤32 个），弧 `d→d'` 存在当且仅当 `d` 所达节点恰为 `d'` 所出节点，权为进入管段长度 + 节点处转接耗时（禁行则无弧）。

1. 在 `(已覆盖管段位掩码 M, 当前穿越状态 d)` 上做前向 DP：层内用仅走已覆盖管段弧的**多源 Dijkstra 闭包**（≤32 状态，O(S²) 选择式）处理同层折返，首次踏上新管段则升掩码；同时精确累计**最优路线数**；
2. 反向 DP 同法在逆弧上做层内闭包，得到每个状态到闭游终点的最便宜后缀；
3. 从检修口出发的所有最优首步中选总代价最小者，再逐步选择仍能达成最优后缀的、按 `(管段标识序, 方向)` 字典序最小的下一状态，恢复**规范闭游**；
4. 全部最优终态（覆盖全部管段且回到检修口）不可达时即为无可行闭游。

## 本地运行（无 Docker）

```bash
python3 -m venv .venv && . .venv/bin/activate
pip install -r requirements.txt
gunicorn -w 2 -b 0.0.0.0:8000 app.server:app
# 浏览器打开 http://localhost:8000
```

## Docker / Compose

```bash
# 构建并启动（宿主机端口可用 HOST_PORT 覆盖，默认 8080）
HOST_PORT=9090 docker compose up -d --build
# 健康检查
curl http://localhost:${HOST_PORT:-8080}/health
```

## 一键核对（verify 单次服务）

名为 `verify` 的服务依次执行：代码测试 → 奇度管网同优分类/欧拉零增程边界 → 转接模式边界（高耗时绕行、禁行无解）→ 镜像构建 → HTTP 冒烟，然后退出，以退出码报告结果。

```bash
# 方式一：编排脚本（包含构建 + 健康等待）
./scripts/verify.sh
HOST_PORT=9090 ./scripts/verify.sh

# 方式二：手动
docker compose build
docker compose up -d web            # 等待 healthy
docker compose run --rm verify      # 退出码 0 表示全部通过
```

不经过容器单独运行核对（会自行拉起临时 gunicorn）：

```bash
python -m app.verify
```

- `tests/test_transfer.py`：转接模式确定性用例（高耗时绕行、禁行无解/可绕行、平行管段、规则校验）+ 30 组随机图对**闭游 DFS 暴力 oracle**（独立的无预算可达性 BFS + 按求解器最优值截断的 DFS 枚举）的交叉验证（最优总耗时、精确路线数、规范序列）；
- `tests/test_api.py`：HTTP 序列化（两种模式）、错误定位、畸形请求。

## 页面

左侧可切换普通/转接模式并编辑节点、管段、检修口与转接规则；成功后中部按模式展示：普通模式为总长度、增程、同优集合数量、位向量与按颜色分类的管网图；转接模式为**行走长度、转接耗时、总耗时**、规则命中清单与管网图。右侧为逐步闭合路线。点击图中管段可高亮其全部经过位置；转接模式下点击某条规则可高亮路线中**全部命中步**（绿色），禁行规则无命中。

## API

`POST /api/audit`

普通模式：

```json
{
  "nodes": ["A", "B", "C", "D"],
  "edges": [
    {"id": "e1", "u": "A", "v": "B", "length": 1}
  ],
  "start": "A"
}
```

转接耗时模式（`transferMode:true`；`cost` 为非负整数、`-1`/`"禁行"` 表禁行，缺省为 0）：

```json
{
  "nodes": ["A", "B", "C"],
  "edges": [
    {"id": "e1", "u": "A", "v": "B", "length": 1},
    {"id": "e2", "u": "B", "v": "C", "length": 1}
  ],
  "start": "A",
  "transferMode": true,
  "rules": [
    {"node": "B", "edgeA": "e1", "edgeB": "e2", "cost": 10}
  ]
}
```

普通模式成功返回历史字段（`totalLength`、`addedLength`、`optimalCount`、
`canonicalVector`、`canonicalEdges`、每边 `classification`、`route`、`positions`、
`eulerian`、`oddVertices`），新增 `mode:"normal"`；这些字段全部保持原义兼容。

转接模式成功返回 `mode:"transfer"`、`walkLength`（行走长度）、`transferCost`（转接耗时）、
`totalTime`（总耗时）、`optimalCount`（**精确最优路线数**）、`addedLength`（重复长度）、
每步 `transfer`（进入该步的转接耗时）与 `ruleRef`（命中的有序管段对，无则为 null）、
`rules[].positions`（该规则在规范路线中的全部命中步序号；禁行规则必为空）、
`route`（按管段标识与方向序列字典序裁决的规范步骤）及每管段 `copies`。

两种模式失败均返回 `ok:false`、`error`、`fields`、`locations`（含表名与行号）。
规则引用错误、非相邻管段或无可行闭游时保留输入并清除旧结论（前端行为）。
