# 低温冷却管网巡检审计（中国邮路问题）

巡检机器人必须从指定检修口出发、回到原处，且至少走过每条管段一次。本服务求解无向多重图上的**中国邮路 / 路由巡检问题**：

- 在每条管段均走一次的基础上，选出需要**额外重复**的管段集合，使所有节点度数为偶数；
- 增加总长度**最小**；
- **精确给出全部同优集合数量**（按不同边集合计数，平行管段与等长最短路造成的分解歧义已去重）；
- 按**边标识字典序**生成 `0` 优先规范位向量并确定规范集合；
- 依据全部最优集合把每条管段标为 **必重复 / 可重复 / 从不重复**；
- 为规范集合生成一条从检修口起止、逐步可核对、副本数精确吻合的闭合欧拉路线。

## 转接耗时模式

在管网编辑区切换到「转接耗时模式」后，可为**同一节点处两条不同管段的无序转接**填写规则：

- 非负整数耗时；留空（未填写）视为 **0**；填写 `禁行`/`x`（或 `forbidden:true`）表示**禁行**；
- 仅可引用已存在的管段，且两条管段必须有公共节点；同一对管段规则唯一、不可与自身配对；
- 同一管段原路折返始终零耗时（叶子管段只能这样巡检）；
- 平行管段按标识分别转接；
- 启用该模式时管段不超过 16 条。

目标是从检修口出发、回到检修口、每条管段至少经过一次（允许任意重复经过管段）的闭合行走，最小化

```
总耗时 = Σ 走过的管段长度 + Σ 每次相邻转接耗时
```

后端**直接在可重复经过管段的闭合行走空间中求全局最优**，不会先固定普通模式的最小增程集合再重排。返回行走长度、转接耗时、总耗时、**最优路线数（精确计数）** 以及按「管段标识序、再按方向」字典序裁决的规范步骤；每条转接标记其命中的规则。点击规则（或路线中的转接标记）会高亮该规则在路线中的**全部命中位置**；禁行规则不会出现在任何路线中，否则该实例无可行闭游。

### 转接模式算法要点（`app/solver.py: audit_transfer`）

每条无向边展开为两个有向镖（darts，`2i` 为 u→v、`2i+1` 为 v→u）。状态为

```
(已覆盖管段掩码 S, 当前所在有向镖 d)
```

从检修口的出发镖（初始代价为该镖长度）起，沿镖头节点的可行转接转移：同边反向镖代价 0（折返，仅付回程长度），其他镖付规则耗时加该镖长度，禁行转接不连边。在该分层状态图（最多 2^16·32 个状态）上 Dijkstra 求全局最优；所有边权至少为正管段长度，故最短状态路无环，弹出时即可精确累计最优选路数量。终点为覆盖全部边且镖头回到检修口的状态。规范路线经紧边反向标记后，按镖序（标识字典序、正向优先）贪心确定。

## 约束与校验

- 2–18 个唯一 ASCII 节点（非空白可打印字符）；
- 1–32 条管段，唯一 ASCII 标识、正整数长度；转接耗时模式下不超过 16 条；
- 允许平行管段，禁止自环；
- 检修口必须是已声明节点；
- 断连、未知端点、重复标识、非法长度、不存在的检修口都会返回错误，并在页面定位到具体表/行；
- 转接模式下规则引用不存在管段、非相邻管段配对、自身配对、非法耗时、重复规则同样定位到规则表行；
- 按当前禁行规则不存在可覆盖全部管段并返回检修口的闭游时返回「无可行闭游」；
- 审计失败时页面保留输入并清除旧结论。

## 算法要点（`app/solver.py`）

重复边集合是一个 T-join：重复边子图中恰为原奇度节点的节点度数为奇。

1. 全源 Dijkstra 得到奇度节点间最短路距离；
2. 奇度节点子集完美匹配 DP（O(2^k·k²)，k≤18）求最小增程；
3. 以匹配 DP 为门控，逐掩码合成“奇度锚点的一条最短路”与“剩余子问题的最优集合”的**对称差**，用整数掩码天然去重，得到**全部不同的最优 T-join**（小规模实测毫秒级）；
4. 集合按位向量（边标识序、`0` 优先）取最小者为规范集合；按边在全部最优集合中的出现情况分类；
5. Hierholzer 在扩展多重图上生成规范闭合路线，并对同边副本按经过次序编号。

## 一键核对（verify 单次服务）

名为 `verify` 的服务依次执行：代码测试 → 奇度管网同优分类边界 → 欧拉管网零增程边界 → 镜像构建 → HTTP 冒烟，然后退出，以退出码报告结果。

```bash
# 方式一：编排脚本（包含构建 + 健康等待）
./scripts/verify.sh
HOST_PORT=9090 ./scripts/verify.sh

# 方式二：手动
docker compose build
docker compose up -d web            # 等待 healthy
docker compose run --rm verify      # 退出码 0 表示全部通过
```

不经过容器单独运行核对（会自行拉起临时 gunicorn）：

```bash
python -m app.verify
```

## 页面

顶部可切换普通审计 / 转接耗时模式。左侧编辑节点/管段/检修口（转接模式下另编辑转接规则表）并发起审计。

- 普通模式：中部展示总长度、增加长度、同优集合数量、规范位向量与按颜色分类的管网图（力导向布局，平行管段分离绘制），右侧为逐步闭合路线；
- 转接模式：中部展示行走长度、转接耗时、总耗时、最优路线数与全部规则（禁行规则单独标记），右侧为带转接标记（付费/零耗时/同管折返）的逐步规范路线。

点击图中管段或标签可高亮其在路线中的**全部经过位置**；点击某条转接规则或路线中的转接标记，可高亮该规则在路线中的**全部命中位置**。

## API

`POST /api/audit`

普通模式（`transferMode` 缺省或为 false；返回字段与旧版完全兼容，并额外返回 `"mode":"normal"`）：

```json
{
  "nodes": ["A", "B", "C", "D"],
  "edges": [
    {"id": "e1", "u": "A", "v": "B", "length": 1}
  ],
  "start": "A"
}
```

转接耗时模式（`"transferMode": true`，管段不超过 16 条）：

```json
{
  "nodes": ["A", "B", "C"],
  "edges": [
    {"id": "a", "u": "A", "v": "B", "length": 1},
    {"id": "b", "u": "B", "v": "C", "length": 1},
    {"id": "c", "u": "C", "v": "A", "length": 1}
  ],
  "start": "A",
  "transferMode": true,
  "transfers": [
    {"edgeA": "a", "edgeB": "b", "cost": "100"}
  ]
}
```

`cost` 留空或为 0 表示零耗时，也可填非负整数字符串；填 `"x"`/`"禁行"` 或附加 `"forbidden": true` 表示禁行。成功返回 `ok:true`、`mode:"transfer"`、`walkingLength`、`transferTime`、
`totalTime`、`optimalCount`、逐步 `route`（含每步 `transfer` 与命中的无序 `rule` 边索引对）、
`positions`（每管段全部步序号）、`rulePositions`（每条规则全部命中步序号）及回显的 `rules`
（`cost:null` 即禁行）。

普通模式成功返回 `ok:true`、`totalLength`、`addedLength`、`optimalCount`、`canonicalVector`、
`canonicalEdges`、每边 `classification`（required/optional/never）、`route`（逐步方向与副本号）
及 `positions`（每条边在路线中的全部步序号）。失败返回 `ok:false`、`error`、`fields`、
`locations`（含表名与行号；规则表额外含 `sub` 定位到 edgeA/edgeB/cost）。
